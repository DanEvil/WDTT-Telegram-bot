# WDTT — Telegram-бот продажи доступа (оплата через ЮKassa)

Бот продаёт подписки на **[WDTT](https://github.com/ildarmaga/wdtt)**. После успешной оплаты через **ЮKassa** он автоматически создаёт пользователя в панели WDTT и присылает клиенту ссылки для подключения под каждую платформу — отдельные `wdtt://` ссылки для iOS, Android, Windows и Linux (берутся из подписки в панели; при недоступности отдаётся универсальная ссылка).

## Как это работает

```
Клиент в Telegram
   │  нажимает «🛒 Купить» и выбирает тариф кнопкой
   ▼
Бот создаёт платёж в ЮKassa ──► клиент оплачивает по ссылке
   │  (статус succeeded)
   ▼
Бот вызывает REST API панели WDTT:
   POST /login
   POST /panel/api/users/add   (или /users/update при продлении)
    GET  /panel/api/users       + страница подписки (ссылки по платформам)
   ▼
Клиент получает в Telegram ссылки для iOS / Android / Windows / Linux
```

Статус оплаты бот узнаёт двумя способами: **периодический опрос** (по умолчанию, работает без публичного адреса) и **webhook ЮKassa** (рекомендуется в продакшене — мгновенно).

## Возможности

- **Никаких команд и inline-кнопок** — всё управление кнопками reply-клавиатуры под полем ввода.
- Тарифы настраиваются (срок, цена, трафик, число устройств) — прямо из админ-меню бота или через `PLANS_JSON` при первом запуске.
- Бесплатный **пробный период** (по умолчанию 3 дня) — один раз на пользователя, без оплаты.
- **Реферальная программа**: приглашённый друг оплачивает первую подписку — пригласивший получает +3 дня.
- Покупка через ЮKassa с автоподтверждением (`capture=true`); ссылка на оплату отправляется текстом.
- Продление действующей подписки продлевает тот же ключ (конфиг не меняется).
- Автоматическое удаление истёкших ключей + уведомление клиента.
- **Несколько серверов WDTT**: новые клиенты автоматически распределяются на наименее загруженный сервер; серверы добавляются/удаляются через админ-меню.
- Админ-раздел в клавиатуре (виден только админам); данные для отключения/продления/серверов вводятся сообщениями по подсказкам бота.
- Уведомления админу о каждой оплате и об ошибках выдачи.

## 1. Требования

- **Docker + Docker Compose** (рекомендуется) или Python **3.10–3.13** — aiogram 3 не работает на Python 3.14+.
- Установленный и настроенный **[WDTT](https://github.com/ildarmaga/wdtt)** (панель доступна по `https://IP:2860/wdtt/`).
- Аккаунт **[ЮKassa](https://yookassa.ru/)** (shopId и секретный ключ; для теста — тестовые ключи).
- Telegram-бот от [@BotFather](https://t.me/BotFather).

## 2. Быстрый старт в Docker (рекомендуется)

На чистом Linux-сервере (VPS) — одна команда: скрипт сам установит Docker, склонирует репозиторий, откроет окно настроек и запустит контейнер.

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/DanEvil/WDTT-Telegram-bot/main/deploy.sh)
```

При установке автоматически откроется окно настроек: если в системе есть
`whiptail` — псевдографические диалоги (поля с значениями по умолчанию,
маскированный ввод паролей, экран подтверждения), иначе — обычные подсказки
в терминале. Существующий `.env` не теряется: значения подставляются
в поля по умолчанию, вы лишь подтверждаете или правите поля.

Команды настроек:

```bash
sudo ./deploy.sh --configure        # открыть окно настроек после установки (с перезапуском контейнера)
sudo ./deploy.sh                   # полная установка/перенакат + окно настроек
sudo NONINTERACTIVE=1 ./deploy.sh  # без мастера (нужен готовый .env)
```

Ручной запуск:

```bash
git clone https://github.com/DanEvil/WDTT-Telegram-bot.git && cd WDTT-Telegram-bot
cp .env.example .env
nano .env              # заполните токены и данные панели WDTT
chmod 600 .env
docker compose up -d --build
```

Полезные команды:

```bash
docker compose logs -f wdtt-bot   # логи
docker compose restart            # перезапуск
docker compose down               # остановить
git pull && docker compose up -d --build   # обновление
```

Про файлы Docker:

| Файл | Назначение |
|---|---|
| `Dockerfile` | образ на `python:3.13-slim`, запуск под не-root пользователем |
| `docker-compose.yml` | сервис `wdtt-bot`; база SQLite в docker-томе `bot-data:/app/data` |
| `.dockerignore` | не берёт в образ секреты, базу и служебные файлы |
| `deploy.sh` | автоматическое развёртывание на VPS |

Notes:

- Порт наружу нужен **только для webhook ЮKassa** — блок `ports` в `docker-compose.yml` закомментирован; при `WEBHOOK_ENABLED=true` раскомментируйте его и выполните `docker compose up -d`.
- `.env` и база находятся вне образа и переживают обновление кода.

## 3. Настройка

Скопируйте пример конфигурации и заполните его:

```bash
cp .env.example .env
```

Основные переменные:

| Переменная | Описание |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather |
| `ADMIN_IDS` | ваш Telegram ID (узнать у @userinfobot), через запятую |
| `YOOKASSA_SHOP_ID` | идентификатор магазина ЮKassa |
| `YOOKASSA_SECRET_KEY` | секретный ключ ЮKassa (для теста — `test_...`) |
| `RETURN_URL` | ссылка на бота (`https://t.me/YourBot`) |
| `WDTT_BASE_URL` | базовый URL панели, напр. `https://1.2.3.4:2860/wdtt` |
| `WDTT_USERNAME` / `WDTT_PASSWORD` | логин/пароль панели WDTT |
| `WDTT_VERIFY_SSL` | `false`, если панель за самоподписанным сертификатом |

Остальные `TRIAL_*`, `REFERRAL_*`, `POLL_INTERVAL`, `WEBHOOK_*`, `PLANS_JSON` описаны в `.env.example`.

## 4. Настройка панели WDTT

1. Зайдите в панель и **смените пароль по умолчанию** (`admin`/`wdtt`) — см. README WDTT.
2. Убедитесь, что `max_users` в настройках входа достаточно для числа клиентов.
3. Убедитесь, что панель доступна с сервера бота (если бот на той же машине — `https://127.0.0.1:2860/wdtt`; в Docker — не `localhost`, а IP хоста).
4. Если используется самоподписанный SSL — оставьте `WDTT_VERIFY_SSL=false`.

> ⚠️ Не публикуйте панель WDTT в открытый интернет без HTTPS и без смены пароля. Панель не имеет rate-limit.

## 5. Настройка ЮKassa

1. В личном кабинете ЮKassa возьмите `shopId` и **секретный ключ** (раздел «Интеграция» → «Ключи API»).
2. Для тестов используйте **тестовый магазин** (тестовые shopId/ключ, карта `1111 1111 1111 1026`).
3. Для автоматического приёма оплаты настройте **webhook** (раздел «Webhooks» в ЛК) — необязательно, но рекомендуется:
   - URL: `https://your-domain/yookassa`
   - Событие: `payment.succeeded`
   - В `.env`: `WEBHOOK_ENABLED=true`; раскомментируйте `ports` в `docker-compose.yml` и пробросьте порт наружу через HTTPS (например, через nginx/caddy).

Без webhook бот проверяет статус неоплаченных платежей раз в `POLL_INTERVAL` секунд.

### Важно про чеки (54-ФЗ)

Для ИП/юрлиц в РФ продажа услуги требует **выдачи чека**. В `payments.py` есть готовый (закомментированный) блок `receipt` — раскомментируйте его и заполните email/телефон клиента (сейчас email не запрашивается; при необходимости добавьте шаг сбора email до оплаты).

## 6. Кнопки бота

Списка команд у бота нет вообще (кнопки меню Telegram скрыты). `/start` остаётся техническим обработчиком: без него Telegram не покажет меню и не будут работать реферальные ссылки (`https://t.me/bot?start=ref_<tg_id>`).

| Кнопка | Кому | Описание |
|---|---|---|
| 🎁 Пробный период | клиент | бесплатный пробный период (один раз) |
| 🛒 Купить | клиент | выбрать и оплатить тариф (тарифы — кнопками `💳 …`) |
| 👤 Профиль | клиент | моя подписка и ссылки `wdtt://` (iOS/Android/Windows/Linux) |
| 👥 Рефералы | клиент | реферальная ссылка (+3 дня за друга) |
| 📖 Инструкция | клиент | инструкция по подключению |
| ❓ Помощь | клиент | помощь |
| 🏠 Главное меню | клиент | назад в меню (отменяет текущий ввод) |
| 📊 Статистика | админ | клиенты, выручка |
| 👥 Клиенты | админ | список активных клиентов |
| ⛔ Отозвать | админ | отозвать доступ (бот спросит Telegram ID) |
| ➕ Продлить | админ | продлить вручную (бот спросит ID и число дней) |
| 🖥 Серверы | админ | список серверов и нагрузка |
| ➕ Добавить сервер | админ | добавить сервер WDTT (4 шага: имя, URL, логин, пароль) |
| 🗑 Удалить сервер | админ | удалить сервер (бот спросит ID) |
| 🗂 Тарифы | админ | список тарифов (id, цена, срок, трафик, устройства) |
| ➕ Добавить тариф | админ | создать тариф по подсказкам (6 шагов: ID, название, дней, цена, ГБ, устройств) |
| ✏️ Изменить тариф | админ | изменить срок/цену/трафик/устройства (бот спросит ID и 4 значения строкой) |
| 🗑 Удалить тариф | админ | удалить тариф (бот спросит ID) |

## 7. Запуск без Docker (venv + systemd)

```bash
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python bot.py
```

Для фонового запуска на Linux создайте systemd-сервис:

```ini
# /etc/systemd/system/bot.service
[Unit]
Description=WDTT sale bot
After=network.target

[Service]
WorkingDirectory=/opt/wdtt-bot
ExecStart=/opt/wdtt-bot/.venv/bin/python /opt/wdtt-bot/bot.py
Restart=always
RestartSec=5
EnvironmentFile=/opt/wdtt-bot/.env

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now bot
sudo journalctl -u bot -f
```

Для обновления кода в этом варианте есть скрипты:

```bash
# Linux (VPS). Если папка ещё не git-репозиторий, при первом запуске укажите repo:
REPO_URL=https://github.com/ВАШ_ЛОГИН/ВАШ_РЕПО.git ./update.sh
# последующие обновления: ./update.sh
# конкретная ветка: BRANCH=dev ./update.sh
```

```powershell
# Windows
.\update.ps1
```

Скрипты работают одинаково и выбирают путь автоматически:

1. Привязывают папку к репозиторию (если это ещё не git-репозиторий; `REPO_URL` нужен только при первой привязке или смене репозитория).
2. Определяют ветку (`main`/`master` или `BRANCH`) и забирают код: `git reset --hard origin/<ветка>` — код приводится точно к версии из репозитория. `.env` и база не отслеживаются (`.gitignore`) и сохраняются — но **незакоммиченные локальные правки кода будут затёрты**.
3. Применяют обновление:
   - **Docker найден** (основной путь): `docker compose up -d --build` — пересборка и перезапуск контейнера (и в `update.sh`, и в `update.ps1`).
   - **Docker нет** (только `update.sh`, Linux): обновят зависимости в `.venv` (Python 3.10–3.13) и перезапустят systemd-сервис (`SERVICE`, по умолчанию `bot`).
   - **Docker нет** (только `update.ps1`, Windows): обновят зависимости в `.venv`; бота запускают вручную: `.\.venv\Scripts\python.exe bot.py`.

## 8. Структура проекта

```
WDTT-Telegram-bot/
├── bot.py             # Telegram-хендлеры (reply-кнопки, FSM), выдача доступа, фоновые задачи
├── config.py          # конфигурация из .env
├── db.py              # SQLite (клиенты, платежи, серверы, тарифы)
├── wdtt.py            # клиент REST API панели WDTT (логин, CSRF, ссылки wdtt://)
├── payments.py        # создание/проверка платежей ЮKassa (REST API v3)
├── webhook.py         # HTTP-webhook ЮKassa (необязательно)
├── plans.py           # тарифы (можно переопределить через PLANS_JSON)
├── smoke_test.py      # смоук-тест без реальной панели/ЮKassa (заглушка)
├── Dockerfile         # образ (python:3.13-slim)
├── docker-compose.yml # сервис + том для базы
├── .dockerignore
├── deploy.sh          # автоматическое Docker-развёртывание на VPS
├── update.sh / update.ps1  # обновление кода для venv+systemd
├── requirements.txt
├── .env.example
└── README.md
```

Данные хранятся в SQLite (`bot.db`; в Docker — `/app/data/bot.db` в томе `bot-data`): таблицы `customers` (подписки), `payments` (платежи: pending → paid → fulfilled/cancelled), `trials` (использованные пробные периоды), `referrals` (рефералы), `servers` (серверы WDTT), `plans` (тарифы). Ключи доступа генерируются панелью WDTT.

## Проверка

```bash
pip install -r requirements.txt
python smoke_test.py
```

Тест поднимает заглушку панели WDTT и проверяет клиент API, SQLite-слой, создание/продление подписок, реферальный бонус и webhook — без реального Telegram и ЮKassa.
