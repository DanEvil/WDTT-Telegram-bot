WDTT — схема работы сервера

Клиенты → xray (VLESS REALITY / XHTTP) → wdtt-socks (netns) → VK TURN-релеи → интернет · панель и бот управляют доступом

Вход: VLESS-инбаунды xray

  • • vless-in :443 — TCP+REALITY, sni=ya.ru, flow=xtls-rprx-vision
  • • vless-xhttp-in :20500 — XHTTP packet-up, спрятан за app.ko-gateway.ru (traefik → /xhttp), для белых списков РФ
  • • per-user UUID: бот заводит через xray api adu :62790, sync.service перезаливает users.json после рестарта

Маршрутизация xray

  • • geoip:private → blocked
  • • udp/53 и geoip:ru → direct (RU-сайты и DNS идут напрямую, мимо VPN)
  • • всё остальное → wdtt-out (SOCKS5 в netns)

Выход: WDTT через VK TURN

  • • wdtt-socks в netns wdttx: SOCKS5 10.255.254.2:1080 → core (UDP 127.0.0.1:19000) → TUN ⇄ veth
  • • core → DTLS :56000 + WRAP к TURN-релеям VK (маскировка под видеозвонок)
  • • выходной IP — 78.17.16.23; панель :2860 выдаёт wdtt:// ссылки
