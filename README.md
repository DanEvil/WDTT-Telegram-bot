# WDTT Telegram-бот продажи подписок

Telegram-бот, который продаёт подписки на VPN-панель [WDTT](https://github.com/ildarmaga/wdtt).
Клиент оплачивает тариф через **ЮKassa**, бот автоматически создаёт/продлевает пользователя
в панели и выдаёт ссылки для подключения iOS/Android.

> Бот управляет панелью через её REST API (логин/пароль админа из `.env`) — сам код панели не нужен.

## Возможности

- **Постоянное reply-меню** (`is_persistent`): кнопки всегда свёрнуты в плашку снизу и не пропадают.
- **Автоочистка чата**: при переходе в другой пункт меню (или `/start`) бот удаляет всю старую переписку, включая нажатую кнопку; клавиатура остаётся на месте.
- **Покупка тарифов**: список тарифов из БД (CRUD в админке) или `PLANS_JSON` в `.env`.
- **Пробный период**: один раз на пользователя (по умолчанию 3 дня, 5 ГБ, 1 устройство — настраивается).
- **Реферальная программа**: ссылка `https://t.me/<bot>?start=ref_<tg_id>`, +3 дня подписки после первой оплаты приглашённого.
- **Подарочные подписки** (админ): любая длительность по Telegram ID, дни суммируются, клиент получает уведомление.
- **Несколько серверов WDTT**: панель с наименьшей загрузкой выбирается автоматически; серверы добавляются из админки.
- **Платформенные ссылки**: для iOS и Android берутся со страницы подписки панели; при недоступности — откат на универсальную `wdtt://`.
- **vk_hash автоматически**: если `WDTT_VK_HASH` не задан, бот создаёт VK-вызов через панель (`POST /panel/api/vk/call/create`); пустые значения и плейсхолдер `VK_HASH` отбрасываются.
- **Инструкция в боте**: только Android (CSQTT / WDTT APK) и iOS (TestFlight) — с кликабельными ссылками и тремя пошаговыми скриншотами с подписями.
- **Оплата ЮKassa** (REST API v3, `capture=true`): webhook (рекомендуется) или опрос платежей по интервалу.
- **Админ-панель**: статистика, клиенты, продление/отзыв/подарок, серверы, тарифы.

## Быстрая установка (Linux VPS, Docker)

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/DanEvil/WDTT-Telegram-bot/main/deploy.sh)
```

`deploy.sh` сам ставит зависимости (Docker, git, curl, whiptail), клонирует проект, проводит
интерактивный мастер настроек (TUI whiptail, фолбэк на подсказки в консоли; пароли скрыты,
в конце показывается сводка) и запускает проект:

1. **Зависимости** — docker, git, curl, whiptail/dialog.
2. **Клонирование** — по умолчанию этот репозиторий (можно форк).
3. **Мастер настроек** — заполняет `.env`.
4. **Ежедневная перезагрузка сервера** — опционально (`daily-reboot.service` + `timer`), можно переназначить время или удалить таймер.
5. **Сборка и запуск** — `docker compose up -d --build`.
6. **Автозапуск при перезагрузке** — `systemctl enable docker` и сервис `wdtt-bot.service` (поднимает контейнер при старте сервера).

Повторный запуск и служебные режимы:

```bash
sudo ./deploy.sh --configure        # изменить только .env (пустой ввод = оставить текущее значение)
sudo NONINTERACTIVE=1 ./deploy.sh   # без вопросов; требуется уже заполненный .env
```

Проверка состояния:

```bash
systemctl status wdtt-bot.service        # автозапуск
systemctl list-timers daily-reboot.timer # таймер перезагрузки (если включён)
docker compose logs -f wdtt-bot          # логи бота
```

## Ручная установка (Docker)

```bash
git clone https://github.com/DanEvil/WDTT-Telegram-bot.git && cd WDTT-Telegram-bot
cp .env.example .env
nano .env                 # токен бота, админ ID, ЮKassa, WDTT-панель
chmod 600 .env
docker compose up -d --build
```

| Действие | Команда |
|---|---|
| логи | `docker compose logs -f wdtt-bot` |
| перезапуск | `docker compose restart` |
| остановить | `docker compose down` |
| обновить | `./update.sh` |

Особенности обвязки:

- SQLite-база живёт в docker-томе (`wdtt-bot_bot-data:/app/data/bot.db`);
- `docker-compose.yml` использует `network_mode: host` — webhook ЮKassa работает без внешнего порта-маппинга и нет конфликтов docker-сетей с панелью WDTT на том же VPS;
- контейнер работает от непривилегированного пользователя;
- `.env` не коммитится и содержит секреты — держите сервер под доступом.

## Переменные окружения

| Переменная | Описание |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather |
| `ADMIN_IDS` | Telegram ID админов через запятую (узнать: @userinfobot) |
| `YOOKASSA_SHOP_ID` | shopId ЮKassa |
| `YOOKASSA_SECRET_KEY` | ключ ЮKassa (`test_...` / `live_...`) |
| `RETURN_URL` | ссылка на бота (`https://t.me/YourBot`) |
| `WDTT_BASE_URL` | URL панели WDTT, например `https://1.2.3.4:2860/wdtt` |
| `WDTT_USERNAME` / `WDTT_PASSWORD` | учётка админа панели |
| `WDTT_VERIFY_SSL` | `false`, если самоподписанный сертификат |
| `WDTT_VK_HASH` | опционально: фиксированный vk_hash; иначе бот запрашивает VK-вызов сам |
| `PLANS_JSON` | опционально: JSON со списком тарифов (иначе дефолт из `plans.py`) |
| `TRIAL_DAYS` / `TRIAL_TRAFFIC_GB` / `TRIAL_MAX_DEVICES` | параметры пробного периода (3 / 5 / 1) |
| `REFERRAL_REWARD_*` | дневная/трафик/устройства награды рефереру |
| `WEBHOOK_ENABLED` | `true` — принимать webhook ЮKassa |
| `WEBHOOK_HOST` / `WEBHOOK_PORT` / `WEBHOOK_PATH` | HTTP-сервер для webhook (`/yookassa`) |
| `POLL_INTERVAL` | интервал опроса платежей в секундах (пока webhook выключен) |
| `DB_PATH` | путь к SQLite (в Docker — `/app/data/bot.db`) |

Тарифы по умолчанию (100 ₽ / 30 дн, 300 ₽ / 90 дн, 600 ₽ / 180 дн, 1200 ₽ / 365 дн; трафик безлимит, до 3 устройств) задаются в `plans.py` и редактируются из админки.

## Настройка ЮKassa

1. В личном кабинете возьмите `shopId` и **секретный ключ** рабочего магазина (для тестов — тестовые).
2. Рекомендуемый режим — **webhook**: добавьте URL `https://<ваш-домен>/yookassa`
   (событие `payment.succeeded`) и включите `WEBHOOK_ENABLED=true`.
   Порт должен быть доступен извне (nginx/caddy с HTTPS; благодаря `network_mode: host`
   контейнер слушает `WEBHOOK_PORT` напрямую).
3. Без webhook бот сам опрашивает статусы каждые `POLL_INTERVAL` секунд — ничего дополнительно включать не нужно.

## Настройка панели WDTT

1. Панель должна отвечать по `WDTT_BASE_URL` (обычно `https://IP:2860/wdtt`).
2. Проверьте лимит inbound (`max_users`) — это максимум активных пользователей для этого сервера.
3. Внутренний адрес панели не меняйте без необходимости; при изменении обновите `WDTT_BASE_URL`.
4. Самоподписанный сертификат → `WDTT_VERIFY_SSL=false`.

## Структура проекта

```
bot.py                  # Telegram-логика: меню, FSM, инструкция, выдача доступа
config.py               # конфигурация из .env
db.py                   # SQLite: customers, payments, trials, referrals, servers, plans
wdtt.py                 # REST API панели WDTT; ссылки wdtt://, vk_hash
payments.py             # создание/опрос платежей ЮKassa (v3)
webhook.py              # HTTP-приём webhook ЮKassa
plans.py                # тарифы (дефолт или PLANS_JSON)
smoke_test.py           # smoke-тесты без доступа к реальным API
deploy.sh               # установка на VPS: зависимости + мастер + docker + systemd
update.sh / update.ps1  # обновление репозитория и перезапуск
Dockerfile / docker-compose.yml / .dockerignore
```

БД: `bot.db` (в Docker — `/app/data/bot.db` в томе `wdtt-bot_bot-data`). Таблицы: `customers`, `payments`, `trials`, `referrals`, `servers`, `plans`. Пароли подключения к панели хранятся в БД — берегите доступ к серверу.

## Обновление

```bash
# Linux (VPS), в каталоге работающего бота:
./update.sh          # git pull + docker compose up -d --build (+ реквизиты venv-режима)
# Windows:
.\update.ps1
```

Если каталог был скопирован вручную, укажите `REPO_URL`. Режим без Docker (`update.sh` на Linux) обновит `.venv` и перезапустит systemd-сервис (имя — `SERVICE`, по умолчанию `bot`).

## Запуск без Docker

python -m venv .venv
